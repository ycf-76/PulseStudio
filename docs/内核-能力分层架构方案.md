# 内核-能力分层架构方案（Claude Code 式演进路线）

> 版本：v1.0（2026-10-19）
> 状态：方案评审稿，待大哥批准后按期执行
> 一句话：内核定稿冻结（接口契约，不是代码封版），能力层分期外置，技能加载即用。

---

## 1. 背景与目标

平台当前是单体 FastAPI 后端 + Vue 3 前端。长期方向对标 Claude Code 的 harness 架构：

- **内核（harness）做稳冻结**：循环、协议、沙箱边界这三样不常变的东西，定稿后接口不再变；
- **能力层可插拔**：模型、工具、界面、重能力（视频/图像/发布）做成可替换、可外置的服务；
- **技能加载即用**：.md / .py 技能按需加载，加减技能不碰内核。

**为什么现在做**：当前内核与能力互相渗透——SSE 事件契约靠默契、截断标记被 `_format_final_output` 白名单滤掉（前端永远不知道任务被截断）、`_dispatch` 里长着视频业务名、技能注入策略硬编码。契约不稳，能力层永远拆不出去。

## 3. 目标架构

```
┌─────────────────────────────────────────────────┐
│  界面层（可插拔） Vue3 ChatView · SSE 流式渲染      │
├─────────────────────────────────────────────────┤
│  契约带① 事件协议：消息/tool_call/流式 token        │
│           （schema 版本化 + ended_reason 枚举）    │
├─────────────────────────────────────────────────┤
│  内核（harness · 定稿后冻结）                      │
│   ReAct 循环 │ 治理上下文 │ 权限门禁 │ 事件流协议    │
├─────────────────────────────────────────────────┤
│  契约带② 统一工具协议：list / call / health        │
│           ToolTransport 双传输 · 可桥接 MCP        │
├─────────────────────────────────────────────────┤
│  能力层（可插拔，内核零感知）                       │
│   内置工具(进程内) │ 能力服务(HTTP外置) │ 技能加载器  │
└─────────────────────────────────────────────────┘
```

### 3.1 内核包含什么（且仅包含）

| 模块 | 内容 | 对应代码 |
|---|---|---|
| ReAct 循环 | 纯状态机：进 session → 出 action → 收 observation | `engine/reactor/` |
| 治理上下文 | token 预算、熔断、压缩、会话历史 | `engine/governance/` |
| 权限门禁 | 澄清三分层、guardian 风险评级、权限校验——唯一调用出口 | `_dispatch` 管道 |
| 事件流协议 | SSE 事件枚举、ended_reason、schema_version | 待新建 `engine/protocol/` |

**内核红线**：grep 不到任何业务工具名（multi_image_video、publish 等）；不 import 任何具体模型 adapter。

### 3.2 两条契约带（冻结对象）

**契约带① 事件协议（内核 ↔ 界面）**

- SSE 事件类型枚举化，pydantic 模型定义，带 `schema_version`；
- loop 每次结束必须给出 `ended_reason`：`completed / max_iterations / token_budget / nudge_exhausted / clarification_paused / error`；
- 改动规则：只加字段不删字段，旧字段标废弃。

**契约带② 工具协议（内核 ↔ 能力层）**

- 三个方法：`list`（能力清单+参数 schema+权限声明）/ `call`（执行）/ `health`（探活）；
- 双传输实现 `ToolTransport`：
  - `InProcessTransport`——进程内直调，开发模式，永久保留；
  - `HttpTransport`——本机 HTTP 调外部能力服务（**Windows 上不用 stdio MCP transport**，子进程管理是坑）；
- MCP 兼容：一个 adapter 文件把三方法桥到 MCP 的 tools/list、tools/call，不必现在引入 MCP 框架；
- BaseLLM 返回结构取"公共子集 + raw 原样透传"，防模型特有字段泄漏进协议。

### 3.3 技能加载（三级渐进披露）

| 级别 | 内容 | 何时进上下文 | token 预算 |
|---|---|---|---|
| L1 索引 | 名称+一句话描述+触发词+分类 | 常驻 system prompt | ≤5000 字符（复用 `build_compact_catalog`） |
| L2 清单 | 参数 schema + 权限声明 + 正文长度 | 命中触发词时 | 索引的补充 |
| L3 正文 | .md 正文 / .py 执行体 | LLM 实际调用该技能时才注入 | 单技能上限（超限用摘要） |

- 技能元数据（tier/触发词/权限/成本）随注册声明，`CREATION_TYPE_SKILLS` 字典迁入元数据；
- 加减技能 = 改目录 + 重扫注册表，四期后支持 watcher 热加载。

## 4. 四期演进路线

> 原则：每期结束主干可跑；先协议化后外置（③必须踩在②上）；真机 LLM 测试由大哥手动触发，验证一律离线 mock/单测。

### 一期：内核定稿（地基，改动最小收益最直接）

| 任务 | 改动点 | 验收 |
|---|---|---|
| ended_reason 枚举 | `session.py` 出口三处（for-else L604-607、token 熔断 L240、nudge 用尽、clarification break L602） | 每种结束原因前端都能显示 |
| `_format_final_output` 放行 ended_reason | L679-694 白名单加一个键 | SSE `node_completed`/`workflow_completed` 带枚举 |
| SSE 事件 schema 化 | 新建 `engine/protocol/events.py`，事件类型枚举 + pydantic 模型 | 契约测试锁定事件结构 |
| 契约测试 | 新建 tests/contract/ | 改契约必红 |

### 二期：全量走协议（内核提纯）

| 任务 | 改动点 | 验收 |
|---|---|---|
| 业务注入改中间件 | L1057-1089 的 image_asset_ids 注入、L1036-1075 skill_call 特判 → dispatch 中间件链 | `session.py` grep 不到业务工具名 |
| ToolTransport 抽象 | L1128 执行点换成 transport 接口，先只有 InProcess 实现 | 内核代码零改动可切传输 |
| CREATION_TYPE_SKILLS 搬家 | registry.py L219-275 → 技能元数据/配置 | registry 只读不定义 |
| 恢复 hot/warm/cold 过滤 | `select_skills` 接回过滤，max_tools/字符预算可配置 | 注入量可控，可回归对比 |
| 技能 L3 正文按需注入 | 命中触发词 → 调用时才灌正文 | 全量注入回潮杜绝 |

### 三期：重能力外置

| 任务 | 改动点 | 验收 |
|---|---|---|
| 拆独立 FastAPI 服务 | 视频合成 / 生图 / 发布 / 爬虫各自成服务，实现工具协议三方法 | 服务独立启停、health 可探 |
| HttpTransport 接入 | 配置切换 local/remote | 内核代码零改动切换 |
| mock↔real 变 local↔remote | 沿用 adapters 现有范式 | 同一契约测试双跑 |
| 服务注册与发现 | 配置文件声明服务地址+权限 | 内核按注册装配 |

### 四期：技能热加载

| 任务 | 改动点 | 验收 |
|---|---|---|
| 目录 watcher | skills 目录变更触发重扫注册 | 新技能丢进目录，下轮对话可用 |
| 技能权限声明 | 每技能 manifest 声明所需权限 | 未声明权限的调用被门禁拦 |
| 摘要降级 | 超长正文自动摘要注入 | 单技能 token 超限不炸上下文 |

## 5. 冻结策略（什么是冻结）

**冻结 = 冻接口契约，不冻代码实现。**

- 冻结范围仅三样：工具协议三方法、事件 schema 与 ended_reason、`_dispatch` 管道顺序与"唯一出口"语义；
- 内核内部实现（loop 优化、压缩重写、guardian 换算法）随时可改，契约测试绿即可；
- 执行手段：契约测试（谁改契约谁红）+ schema_version（加字段不删字段）；
- 不扩大化：业务代码、前端样式、技能内容不在冻结范围。

---

## 6. 风险与坑（前置声明）

1. **跳期返工**：③外置必须踩在②协议化之上，否则各服务协议打架，二次返工；
2. **调试链路变长**：外置后进程/端口/超时/序列化都是排查点，InProcess 永久保留，配置一键切回；
3. **token 回潮**：正文按需 ≠ 无限灌，L1/L3 都有硬预算；`select_skills` 全量注入是现存回潮点；
4. **Windows stdio 坑**：外部服务一律本机 HTTP，不搞 stdio 子进程传输（参考历史上 _procs.txt/_kill.txt 的进程管理混乱）；
5. **`_steps` 等大对象**：不得顺手放进 SSE 事件，明细留在 POST 响应，事件只走枚举和统计值；
6. **真机成本**：所有验证用离线 mock/单测；真机 LLM/云服务调用由大哥手动触发，狗蛋不自动执行。
