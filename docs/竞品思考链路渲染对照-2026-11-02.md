## 一、Claude 真身的五个核心机制

### 1. 思考块默认只有一行（AssistantThinkingMessage.tsx）

非 transcript / 非 verbose 模式下，思考块渲染为：

```
∴ Thinking (ctrl-o to expand)
```

就一行斜体灰字。全文只在 transcript 模式或 verbose 模式才展开。**「思考中滚动一大段推理」在真身里根本不存在**——思考是默认隐藏的，动作才是可见层。

### 2. 读/搜类调用折叠成一句话（collapseReadSearch.ts + CollapsedReadSearchContent.tsx）

连续的 search / read / list 类工具调用被判定为 `isCollapsible`，聚合成 `CollapsedReadSearchGroup`，渲染成**一句带计数的摘要行**：

```
⤿ Searched for 3 patterns, read 2 files
⤿ Ran 3 bash commands, recalled 1 memory
```

关键细节：
- 进行中用现在时动词 `Searching for… / Reading…`（和扫光配合），完成后切过去时 `Searched / Read`
- 低价值细节（每条命令、每个路径）**不进摘要行**，只进展开详情；摘要行只留计数
- bash 快速连续执行时摘要行带 `(${elapsed} · ${lines} lines)` 的实时进度后缀
- verbose 模式是逃生门：所有折叠关闭，逐条原位回放

### 3. 快速调用防闪烁：最短展示时长（CollapsedReadSearchContent.tsx L27）

```ts
const MIN_HINT_DISPLAY_MS = 700;
// Hold each ⤿ hint for a minimum duration so fast-completing tool calls
// (bash commands, file reads, search patterns) are actually readable
// instead of flickering past in a single frame.
```

每条提示至少停留 700ms 才允许被折叠/更新。0.3s 就跑完的 ffprobe 不会一帧闪过。**这就是我们 `animationDelay: i * 45ms` 应该学的东西**——不是按行号累加延迟，而是保证每条新行可读的最短停留。

### 4. 同回合同类调用分组渲染（groupToolUses.ts + GroupedToolUseContent.tsx）

`applyGrouping` 按 `messageId + toolName` 聚合：同一 API 回合里 2 个以上同类型调用合并为 `GroupedToolUseMessage`，**交给该工具自己注册的 `renderGroupedToolUse` 渲染**。分组能力不是渲染器写死的，是每个工具自己声明的。

### 5. 工具可以选择"隐身"（AssistantToolUseMessage.tsx / Tool.ts）

每个工具注册一整套渲染钩子：`userFacingName`（人话名）、`renderToolUseMessage`（一行摘要）、`renderGroupedToolUse`（分组形态）、`renderToolUseProgressMessage`（执行中进度）、`renderToolUseTag`。并且：

- `userFacingName === ''` → 整行不渲染（工具隐身）
- `isTransparentWrapper()` → 排队/完成态 return null，**只有执行中才显示进度**

低层包装类工具（REPL 原语、ToolSearch、memory 写入）走 `isAbsorbedSilently`，被吸收进折叠组、连计数都不占。

## 二、Codex 桌面端：双模式 + Worked-for 披露条（chat-turn.tsx）

- **活跃回合**：过程时间线实时流式——thought、工具行、文本交错出现
- **完成回合**：整个过程收进一个 `CompletedTurnProcessDisclosure`：

```
▸ Worked for 1m 32s
```

点开才有详情；**最终回复正文始终可见**，不被过程淹没
- 顶部常驻 `WorkingTurnStatusStrip`："Working for {计时}"（每秒跳动）
- default 模式 = 交错文本 + 分组工具摘要（可折叠行）；verbose 模式 = 全展开
- 工具行是「统一行」：一行内聚合状态点 + 人话标签 + 时长

## 三、行业 Pattern 归纳（setproduct 归纳 Claude Code / Cursor / ChatGPT Agent / Manus）

1. **Live step ledger**：步骤列表可折叠成单行；展开某一步才看它的工具调用；运行中的步骤钉在可视区
2. **Tool call cards**：**相同连续调用合并成一张卡 + ×N 计数**；时长必须写在卡上（"40s npm install 不写时长会被当成思考"）
3. **Reasoning disclosure**：每步的"Thinking"默认折叠，只露一行摘要；判据："**改变了世界的动作是工具卡，只改变了想法的是 reasoning**"
4. **失败步骤留在原地并标红**——只显示成功的时间线藏住了用户审计需要的故事
5. 子智能体：**返回摘要而非原始中间输出**，嘈杂过程收进子线程

## 四、对照我们的问题 → 修法

| 我们的问题 | 竞品做法 | 对应修法 |
|---|---|---|
| 每个工具调用独占一行（thoughtStream.pushEvent 直通） | Claude 连续读/搜折叠成一句带计数摘要；Codex 完成回合收进 Worked-for | thoughtStream 加聚合层：连续同类调用合并 `×N`，bash/ffprobe 降级为计数 |
| bash 命令文本直接展示 | 摘要行只留计数，命令进展开详情 | 低层命令 label 用意图词（"剪辑处理中"），原文收进「查看执行过程」 |
| `animationDelay: i*45ms` 随行数累加 | Claude 最短展示 700ms（可读性），无行号累加 | delay 封顶 ~200ms；改为"新行动效 + 最短停留" |
| 流式期强制展开无限生长 | Codex 活跃期流式时间线 + 完成收进 disclosure；Claude 思考默认一行 | 流式期只露最近 3-4 行 + 「已执行 N 步」；完成收摘要行（现有行为保留） |
| fallback 噪音行 | Claude `isAbsorbedSilently` 吸收不渲染 | fallback 行默认吸收进调试态 |
| 标签靠前端正则猜 | Claude 每工具注册 `userFacingName`/渲染钩子 | 后端 `tool_call_start` 带 `label`/`phase`；前端按 phase 选动词 |
| 子智能体无分组 | Codex 子智能体收进独立线程；Claude AgentTool 分组渲染 | 子调用挂在 spawn_agent 行下，显示 done/total |
