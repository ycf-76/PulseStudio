思考链渲染方向 · 三选一

同一个任务（「帮我做一期手冲咖啡的选题内容」）在三种渲染方向下的完整生命周期：思考中 → 工具执行 → 输出正文，另附「等待确认」暂停态。每块舞台都可以 重播流式过程、切换 收起/展开、触发 暂停确认。

A · Claude 极简风 —— 「校准面板，不是日志」

默认收起为一行摘要（已思考 Xs · N 个步骤）。展开后是一条细线时间轴：思考行用衬线斜体、工具行小图标 + 灰字 + 真实耗时，旧步骤折叠进「已完成 N 步」。视觉最安静，把注意力留给正文。

优点：最克制、最像「正经生产力工具」；与现有 1:1 移植基础最接近，改造成本低。
代价：时间线仍逐条展示步骤，步骤多时需要折叠条配合；「安静」对内容噪音零容忍，脏数据一眼可见。

B · ChatGPT 播报风 —— 「披露面板兼任进度条」

思考期间只有一行滚动播报（正在检索热点… → 正在做合规校验…），底层步骤聚合成胶囊计数条（搜索热点 ×2、合规校验 ×1），低层命令不逐条露脸。完成后收成一行，悬停/展开才见聚合明细。

优点：等待焦虑最低；天然屏蔽协议噪音（播报文案由后端事件给「人话」，前端零翻译）；步骤再多 UI 也不长高。
代价：过程细节被弱化，审计感弱于 A/C；播报文案需要后端出结构化的「人话摘要」事件。

C · Gemini 计划风 —— 「先亮计划，再逐步打勾」

思考被渲染成一张结构化计划卡：开工先亮 4 步计划，执行时当前步脉冲高亮、完成步打勾落灰、支持在步骤下挂一行思考摘语。可扫读性最强，用户在等待时就知道「它会做什么、做到哪了」。

优点：进度感与掌控感最强，最适合多步骤内容生产流水线（选题→素材→合规→成稿）；计划卡天然承载「暂停在第几步」。
代价：需要后端把 ReAct 步骤映射成语义计划（新协议事件 plan_start / plan_step_update）；计划偏离时要做重排，工程量最大。
