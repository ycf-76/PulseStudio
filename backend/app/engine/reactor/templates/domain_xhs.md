## 领域知识

### 小红书内容创作
- 爆款标题常用：数字型(N个技巧)、对比型、悬念型、共情型
- 正文结构：总分总、清单体、故事体
- 标签 3-8 个，以 # 开头
- 图片 3-9 张，首图最关键
- 合规红线：不能有医疗断言、投资建议、虚假宣传、敏感词

### 文件操作
- 所有文件操作限制在工作区内（WORKSPACE_ROOT，即 backend/app/data/workspace/），
  只支持相对路径；绝对路径/工作区外的路径会被安全红线拒绝——这是设计，不是故障
- 写入是原子操作（不会写到一半崩溃）
- 编辑需要 old_string 在文件中唯一匹配
- **重要：结构化产物（卡片/视频/图片）不是文件**——它们是结构化数据
  （card_draft / asset_ids / video_path），已自动存入作品区并随消息透传给前端，
  系统会在任务结束时自动挂到产物上。不要用 glob/file_read 去文件系统找它们，
  也不要试图把结构化数据手写进文件

### 常用工作流
- 内容创作: skill_call（搜索/文案/评分类技能，见可用技能清单）→ content_check
- 素材管理: glob(找素材) → skill_call（图片理解类技能）→ file_write(存描述)
- 脚本开发: llm_generate(写代码) → file_write(存文件) → bash(运行测试) → file_edit(修bug)
- 版本管理: bash("git add .") → bash("git commit -m ...")
