# 数据卡片打法（minimal_cards）

> 本文件是这套打法风格的唯一来源。平台不解释本文件：创作 agent 自己读、自己照做。
> 适用：数据盘点、榜单、结论先行的事实播报。核心主张——一次只给观众
> 一张卡、一个数字、一个结论。克制是这套打法的全部美学。

## 0. 阅读顺序（规则先行）

- 先通读本文件，再读工作区内其它规则文件，最后才允许打开场景代码。
- 本文件与其余规则冲突时，以本文件为准；规则之间互相矛盾时，
  停下来在回复里说明矛盾点，不要自行仲裁。

## 1. beat = 数据点（与叙事型打法的根本分界）

每个数据点独占一个 beat，一拍一张信息卡。一拍两卡 = 违规。

beat 字段在本打法下的约定写法（timeline 通用校验之上追加）：

- `title`：数据点的一句话结论，必须含数字本身，如「留存率 37%」。
- `visual_task` 固定三段式：「卡：<主体>｜数：<关键数字>｜注：<一行注释，可留空>」。
- `triggers` 不做逐词触发：每拍只放一条 `{"t": t_start, "text": "card-in"}`。
- 单拍时长 4~7s：观众要读完一句结论 + 一个大数字，再留 1s 空白呼吸。

拍与拍的关系只有两种：顺序推进、或以 `compare` 语义成对出现（对比组两拍
共享同一主体标签）。禁止把多个数据点合并成一拍，也禁止为一句话拆成两卡。

本打法硬红线（违反即不合格，review 与 finish 会阻断）：

1. 真人必须入画：口播视频的真人画面是内容主体，必须以 ../frames/（extract_frames
   的原片帧轨）或 ../assets/（matting 抠像轨）作画面层；禁止用 CSS/图形绘制
   假人剪影替代真人。数据卡片打法的「底」与「卡」之外，画面层由真实素材承担。
2. 字形跟随转写：全片文字与 analysis/speech.json 转写一致（简体源全片简体），
   不得自行换用其他字形或语言。
3. 开场纪律：第 1 张卡的 t_start ≤ 1.5s，首屏不许长时间空屏/黑屏。
4. 覆盖纪律：beat 时间轴必须覆盖 [0, 全片时长]，任何 >1s 的空洞与尾部留空
   都是不合格——数据播报讲到哪里，卡就到哪里，片尾不留死底。
5. 底层文字避让：源素材可能自带烧录字幕/水印/台标等底层文字元素
   （prepare_assets 返回的 bottom_elements.suspected 是判断依据）。卡与
   三件套默认避开画面底部 18% 区域；确需放底部时先加全宽暗色渐变压条
   压住底层文字，两层文字不得直接重叠。

## 2. 画面结构：一屏一卡一焦点

- 常驻底：整片一个静态深底，全片不变，不加任何随时间变化的装饰。
- 信息卡：画面上唯一的活动元素。卡内三件套——主体标签、大数字、一行注释——
  一次全部出现，绝不拆开逐个入场。
- 节奏主张：低密度 + 留白。卡占画宽 ≤ 62%，居中偏上；卡外保持大面积空。
  空白不是浪费，是这套打法给观众的读数时间。

## 3. 入场纪律：整卡推入（没有逐词入场）

- 唯一入场动作：t = beat.t_start 时，整卡自下方 24px 处推入到位，历时 320ms、
  缓出曲线。位置与透明度由 seekTo(t) 按时间函数直接计算，不用 CSS transition。
- 唯一退场动作：t = beat.t_end − 0.2s 起，整卡上移 16px 并淡出，历时 200ms。
- 大数字不做滚动、翻牌、计数动画——数字在卡推入时一次到位。
  计数动画制造虚假的过程感，与本打法的克制主张冲突。
- 相邻两卡之间必须存在 ≥ 0.3s 的空底期；禁止卡与卡首尾相接无缝轮播。

## 4. 视觉基调（本打法的风格身份）

- 深底 #0F172A；卡面 #FFFFFF；卡上正文 #0F172A。
- 强调色全片唯一：青 #22D3EE，只用于大数字下方一条 4px 短下划线。
- 大数字用等宽数字（tabular-nums），字号 ≥ 画高 12%；标签与注释用无衬线常规体。
- 卡片圆角、无阴影或极浅阴影；禁用渐变、纹理、emoji 装饰。

## 5. 场景代码规范

- 场景 = scene/index.html + 自带 js，只引用工作区内资产。
- 所有动态量是 t 的纯函数，由 `window.seekTo(t)` 驱动；同一 t 两次渲染
  必须逐像素一致，这是底线。
- 禁随机数（Math.random 等）、禁真实时钟（Date.now / new Date / performance.now）。
- 不用 CSS animation / transition（不受 seekTo 控制）。推入进度手算：
  `p = clamp((t − t_start) / 0.32, 0, 1)`，直接设值。
- 安全区：卡与全部文字距画面边缘 ≥ 80px（1080 宽折算、等比缩放、下限 24px）。

## 6. 自查清单（对齐 review 工具产出）

- [ ] 帧完整：无缺帧报错，帧号连续、无 0 字节（期望帧数 = ceil(duration × fps)）。
- [ ] 时长偏差：实测时长 vs timeline.duration ≤ 1/fps + 0.05s。
- [ ] 响度：loudness.peak 远离 0dB（无削波），rms 落在人声合理区间（约 -24 ~ -12dB）。
- [ ] 安全区：逐拍抽查 contact sheet，卡与三件套全部在安全区内。
- [ ] 一屏一卡：任何一张 contact sheet 上不得同时出现两张信息卡。
- [ ] 空底期存在：相邻两卡之间至少 0.3s 画面只有底色。

自查不过 → 读 review/errors 原文 → 修 timeline 或场景 → 重渲染 → 重查。
自查未全过禁止宣称完成。
