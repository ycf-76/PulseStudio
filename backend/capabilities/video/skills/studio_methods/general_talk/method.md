# 口播叙事打法（general_talk）

> 本文件是这套打法风格的唯一来源。平台不解释本文件：创作 agent 自己读、自己照做。
> 适用：真人出镜口播、观点输出、叙事讲解。核心主张——文字是叙事主角，
> 跟着说话人一起「呼吸」；屏幕上任何时刻只强调一个意思。

## 0. 工作纪律（先读规则再动手）

- 动手前先通读本文件，再读工作区内其它规则文件；没读完规则就写场景代码 = 违规。
- 一切随时间出现、移动、消失的元素，由 `window.seekTo(t)` 驱动：
  给定时间 t，画面状态唯一确定。
- 场景代码禁用随机数（Math.random 等）与真实时钟（Date.now / new Date /
  performance.now 等）——任何导致「同一 t 两次渲染画面不同」的东西都不允许。
  确定性优先于一切视觉效果。
- 不确定就回读规则或 timeline，不要猜；规则之间有矛盾就停下来说明，不要自行仲裁。
- 真人必须入画：口播视频的真人画面是内容主体，必须以 ../frames/（extract_frames
  的原片帧轨）或 ../assets/（matting 抠像轨）作画面层；禁止用 CSS/图形绘制
  假人剪影替代真人——本打法的叙事主角就是说话人本人。
- 底层文字避让：源素材可能自带烧录字幕/水印/台标等底层文字元素
  （prepare_assets 返回的 bottom_elements.suspected 是判断依据）。叠加文字
  默认避开画面底部 18% 区域；确需放底部时，先加一条全宽暗色渐变压条
  压住底层文字再落字，两层文字不得直接重叠。
- 字形跟随转写：全片文字与 analysis/speech.json 转写一致（简体源全片简体），
  不得自行换用其他字形或语言。

## 1. 内容拆解：按语义节拍（beat）划分

把整段口播按「意思」切拍。每个 beat 是一个语义单元，类型从下表选：

| 类型   | 什么时候用             | 典型时长 |
| ------ | ---------------------- | -------- |
| claim  | 抛出观点 / 断言        | 4~8s     |
| quote  | 引用原话 / 他人观点    | 3~6s     |
| stat   | 报数字、给数据         | 3~6s     |
| compare| 对比、转折（A vs B）   | 4~8s     |
| story  | 讲例子、铺垫情节       | 5~10s    |
| cta    | 收尾、行动号召         | 3~5s     |

拆拍规则：

- 拍以语义句号为准：一句话被截成两拍 = 拆错了；一拍塞进两句独立观点 = 拆粗了。
- beats 按 t_start 升序、互不重叠（timeline 校验会打回重叠与倒序）。
- 每个 beat 写清 title（≤12 字）与 visual_task（这一拍画面要干什么，一句话）。
- 相邻两拍允许 0.2s 左右的换气空隙，但禁止长于 1.5s 的空拍——叙事型打法
  靠语流推进，长时间空屏等于断片。
- 开场纪律：第 1 个 beat 的 t_start ≤ 1.5s，首屏不许长时间空屏/黑屏——
  口播开场即开口，画面必须跟着开口走。
- 覆盖纪律：beat 时间轴必须覆盖 [0, 全片时长]；任何 >1s 的空洞与尾部留空
  都是不合格，落 timeline 前先自查两端。

## 2. 双层结构：身后层 + 前景层

- 身后层（back layer）：人物与环境所在，节奏慢。整片只做极缓慢的整体变化
  （如明暗随段落推移），绝不为单个词跳动。
- 前景层（front layer）：文字与强调元素所在，节奏快。文字入场、关键词高亮
  全部发生在这一层。两层一慢一快形成节奏对比，这是本打法动效的总骨架。

## 3. 文字入场纪律：随触发词分时入场

- timeline 里每个 beat 的 triggers[] 按说话顺序给出触发词与触发时刻 t。
- 文字跟触发词走：触发词响起的那一刻，对应词入场——透明度 0→1 加 4px 上移，
  240ms 内完成；同一时刻最多入场一个词。
- 每 beat 内挑 1~2 个关键词，入场后追加一次强调：字号放大 8% 并染强调色。
  强调只给关键词，整句强调 = 没有强调。
- 拍内句子完整出现后保持稳定，直到 t_end 前最后 200ms 整体淡出。
  禁止逐字打字机疯狂刷新（读起来像故障），也禁止整句一次砸出（丢掉语流感）。

## 4. 视觉基调（本打法的风格身份）

- 纸面 #FAFAF9 暖白底；墨字 #1C1917；强调色全片唯一：赭红 #C2410C。
- 标题与字幕用无衬线粗体；数字沿用正文字体，不加等宽。
- 文字密度高：一拍内完整句子进场；强调密度低：一屏最多一处高亮。

## 5. 场景代码规范

- 场景 = scene/index.html + 自带 css/js，只引用工作区内的资产，不外链。
- 所有画面状态是 t 的纯函数：`seekTo(t)` 内只做「算位置 → 设样式」，
  无计时器、无动画循环。
- 不用 CSS animation / transition（它们不受 seekTo 控制）；
  入场进度由 js 按时间函数直接算值并设样式。
- 坐标全部进安全区：元素距画面边缘 ≥ 80px（1080 宽折算、等比缩放、下限 24px）。

## 6. 自查清单（对齐 review 工具产出）

渲染后必读 review/errors 与 loudness，逐条核对，全过才算完：

- [ ] 帧完整：无「缺帧 frame_NNNNNN」报错（期望帧数 = ceil(duration × fps)）。
- [ ] 时长偏差：实测时长与 timeline.duration 之差 ≤ 1/fps + 0.05s。
- [ ] 响度：loudness.peak 未逼近 0dB（无削波）；rms 落在人声合理区间（约 -24 ~ -12dB）。
- [ ] 安全区：抽查 contact sheet，无任何元素贴边或出界。
- [ ] 逐 beat 抽查 contact sheet：文字与触发词同刻出现、全屏强调唯一、
      身后层未随词跳动。

任何一条不过：读错误原文 → 修 timeline 或场景 → 重渲染 → 重查。
自查未全过禁止宣称完成。
